# 第三步：搭时间线（追加）

在第二步的四表之上，按**人物**和**物品**分别建立时间线：索引每个实体的**变化点**，
并标出该状态有效的**章节范围**。

## 与第二步的关系

第二步给出的是**范围**（前 10 章内该实体的样子）。第三步把范围拆成**分段**：
某个属性在第 N 章之前是什么、第 N 章之后变成了什么。

因此第三步只记**变化**，不重抄静态信息。一个实体在范围内没有任何变化，就不出现在时间线里。

## 章节范围怎么写

| 字段 | 说明 |
| --- | --- |
| `from_chapter` | 该状态开始生效的章号；**首次出现**（此前不存在）写 `null` |
| `to_chapter` | 该状态结束的章号；到当前读取范围末尾仍未变则写 `null` |

`from_chapter` 为 `null` 表示这是该实体的首次出现，`from` 写 `"未出现"`。
`to_chapter` 为 `null` 表示「截至所读范围末尾仍然如此」，**不等于**「全书一直如此」。

## 人物时间线 character_timeline

索引对象是人物表里的 `name`。

| 字段 | 说明 |
| --- | --- |
| `name` | 人物名，须能在人物表里对上 |
| `field` | 变化的字段：`age` / `status` / `location` / `identity` / `health` / `appearance` / `relation` / `other` |
| `from_chapter` | 开始章号 |
| `to_chapter` | 结束章号或 `null` |
| `from` | 变化前的值 |
| `to` | 变化后的值 |
| `note` | 原文依据 |

可选 `track` 用于区分同一 field 下的独立状态链，如 other 中的“丧事差务”与“请托外事”。
没有 track 的 other 记录不能仅凭区间重叠就判作矛盾。分段空档表示未记录，不自动填成延续状态。

## 物品时间线 object_timeline

索引对象是物品表里的 `name`。

| 字段 | 说明 |
| --- | --- |
| `name` | 物品名，须能在物品表里对上 |
| `field` | 变化的字段：`owner` / `state` / `location` / `name` / `other` |
| `from_chapter` | 开始章号 |
| `to_chapter` | 结束章号或 `null` |
| `from` | 变化前的值 |
| `to` | 变化后的值 |
| `note` | 原文依据 |

## 原则

- **只记原文明说的变化**，不推算、不脑补。
- 每条都要有原文依据，写进 `note`。
- 时间线里的 `name` 必须能在对应表里对上，不留悬空引用。
- 变化点落在所读范围之外的不收，留给后续追加。
- `age` 的变化沿用第二步的精度写法（确数 / 区间 / 约数）。
