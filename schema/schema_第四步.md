# 第四步：追加（长篇专用）

长篇一章一章读，把新内容追加到第三步的产物上。**短篇跳过本步。**

## 为什么长篇要分章追加

第二步只读了前 10 章，第三步的时间线也只覆盖这 10 章。长篇后面还有几十上百章，
一次性重读成本高、也容易漏。分章追加让每一步只处理一章，可中断、可续跑。

## 每一章做四件事

| 动作 | 说明 |
| --- | --- |
| **加实体** | 本章首次出现的人物/地点/物品/种族，追加到对应四表 |
| **加变化** | 已有实体在本章发生的变化，追加到时间线 |
| **加互动** | 本章人物之间的互动，追加到互动表（须记各方视角，不许简化为主客关系） |
| **加属性** | 作品特有属性，追加到动态属性表（见 `schema_动态属性.md`） |
| **推范围** | 把 `meta.scope` 从「第1-N回」推进到「第1-(N+1)回」 |

**动态属性只在第四步扩展。** 奠基阶段只填四表的核心字段；作品特有属性（判词、境界、灵根……）
在追加时读到才定义。属性名按作品统一，第一次出现时在 `attribute_defs` 里写一句定义。
不许为了填表而编，也不要留空值条目充数。

## 追加时的字段规则

**新实体**：字段与第二步完全一致，`first_chapter` 填本章章号。
`importance` 仍填暂定值，等全文读完再回调。

**新变化**：字段与第三步完全一致。
- 若该实体的上一条变化 `to_chapter` 为 `null`（表示「截至上一步范围末尾仍如此」），
  说明变化发生在**本章**，把它改成 `本章章号 - 1`，再追加新条目。
- 若实体的新状态延续到范围末尾未变，新条目的 `to_chapter` 写 `null`。

**范围推进**：每追加一章，`meta.scope` 与各表的 `meta.scope` 同步更新。

## 遇到矛盾必须 AI 介入研判

追加时一旦发现新章节与已定事实**不一致**，不许默默记一条了事，也不许擅自改旧条目。
必须走研判流程：

1. **停下**，不要继续往下追加。
2. **把矛盾摊开**：新旧两条各自的原文出处、章号、原话。
3. **判性质**，四选一：
   - **原文自身前后不一**（作者笔误、版本差异）→ 两条都保留，在 `note` 里互相标注，写明冲突。
   - **前面抽错了**（旧条目确实不对）→ 记进 `corrections`，写明错在哪、依据是什么，**交人复核后再改**。
   - **看似矛盾实为不同事**（同名不同人、同物不同状态）→ 拆成两条，写清区分依据。
   - **同一实体异写**（一地异名、同一人不同称呼、同一物别名）→ **合并为一条**，异写入 `aliases`；
     目标表没有 `aliases` 字段时转入 `unresolved` 待人工处理。**不要重复建条**。
4. **拿不准就不动**：写进 `unresolved` 并说明卡在哪，留给下一轮或人工。

`conflicts` 不是垃圾桶，是**待研判队列**。每条都要有结论，不能只记现象。

## 不许做的事

- **不许一次读多章**。一章一章来，每章可独立校验。
- **不许推算**。没明说的变化不记。
- **不许擅自改旧条目**。要改必须走上面的研判流程，记进 `corrections` 并交人复核。
- 变化点落在本章之外的，不记。

## 幂等

同一章重复追加不应产生重复条目。追加前先查：该 `(name, field, from_chapter)` 是否已存在。
已存在则跳过，不重复写。
使用可选 track 时，将 track 纳入去重与 range_advance 匹配；不同状态链不能互相收口。

## 输出结构补充

除 `new_entities` / `new_timeline` / `range_advance` / `conflicts` / `unresolved` 外，还有：

| 字段 | 说明 |
| --- | --- |
| `corrections` | 研判结论为「前面抽错了」的条目。写明原条目、错在哪、依据。**不直接改旧文件**，等复核 |
| `conflicts` | 待研判队列；每条须带研判结论与性质判定 |
| `unresolved` | 研判后仍拿不准的，说明卡点 |
