# 维基风格规范 · v0.2fix

本文是写作与渲染的当前标准。目标是百科条目，而非故事复述或文学评论。
审查次数由 [审查配置](审查配置.md) 控制，文风提示不自动触发新一轮 AI 调用。

## 一、百科语言

### 1. 作品外视角与首段

写作者站在作品外，统一使用第三人称。首段先说明主体在作品中的身份，再概述有依据的主要特征。
作品名与作者已知时写出来，不编作者、职业、年龄或身份。

- 人物：孔乙己是鲁迅的短篇小说《孔乙己》中的人物，常在鲁镇的咸亨酒店饮酒。
- 地点：咸亨酒店是小说《孔乙己》中的酒店，位于鲁镇。
- 事件：孔乙己最后一次到咸亨酒店，是小说《孔乙己》结尾叙述的事件。
- 第一人称角色：叙述者是《孔乙己》中未具名的酒店伙计，十二岁起在咸亨酒店工作。

不用“本条目将”“通过这个人物”“故事里的权力边界”等导读或解读。
名词短语可以作短说明，但首段优先使用完整句子，不为躲同语反复检查删掉主语。

### 2. 人称与指代

**第一、第二人称只用于直接引文。** 正文不能继承小说中“我”“我们”“你”的叙事身份。
“我”作为原文角色名时，用“叙述者”或已核实的角色身份称呼；首次说明原文使用“我”。

| 原文或旧写法 | 百科叙述 |
| --- | --- |
| 我从十二岁起在酒店当伙计 | 叙述者十二岁起在咸亨酒店工作。 |
| “我”暗想自己和掌柜的等级还很远 | 叙述者认为自己的地位与掌柜相差很大。 |
| 你会发现孔乙己最后没有回来 | 叙述者此后没有再见到孔乙己。 |
| 他说他把他交给了他 | 写出各动作的承担者与接收者，证据无法辨认时列未决。 |

代词只在同段主体唯一、没有角色切换时使用。两个同性别人物互动、跨段开头或引文后换主体，
恢复姓名或角色名。一句两次出现名字可能是必要消歧，不按次数判错。
“自己”须对应当前句的主语，不把说话人的自称自动变成动作对象。
无名叙述者的性别没有明确证据时用“叙述者”“该人物”，不依据职业或第一人称猜填性别。

### 3. 叙述者、说话人和事实归属

逐句区分叙述者陈述、人物言语、人物推测、梦境与传闻。

- 酒客说孔乙己偷过何家的书，写“酒客指称孔乙己偷过何家的书”，不能直接写“孔乙己偷过何家的书”。
- “警幻仙子所制”若是道人说法，写“道人称……”，不转为物品的已证实来源。
- 叙述者没有再见到人物，不等于人物从此没再来，更不等于人物确定死亡。
- 疑问句不改成断言；动机只在本人表达或原文明确描述时写。
- 原文没有标明说话人，就写“原文未标明说话人”，不根据在场者猜填。

建议在 sources 可选字段记录 speaker、perspective、certainty：
perspective 为 narrator / character / unknown，certainty 为 asserted / reported / inferred / dream。
这些标签辅助核对，不替代原文证据；没有可靠材料时不填。

### 4. 客观、简洁、自然

按身份、经历、特征、关系等主题组织内容，事件条目写经过与结果。
保持现代书面汉语，删除修辞渲染、读者互动、未经证据支持的解释。
转述须形成自然的现代句子，不能把原文削几个字就贴进正文。例如“荐头情面大，辞退不得”
转述为“由于介绍人的关系，掌柜没有辞退叙述者，转而安排其负责温酒”；“一部乱蓬蓬的花白的胡子”
转述为“胡须花白而凌乱”。原作时代词只有在需要说明词义时才保留并解释。
“于是”“随后”“因此”可在原文明确支持的时序或因果关系中使用；不把连接词本身视为错误。
冒号、破折号等正常标点不禁用。问题在内容与语气，不在标点清零。

不逐章以“第 N 章写……”领起，不写流水账。不用“可见”“显然”等替读者作推断；
原文确有人物判断时归属人物，不仅删掉词却留下断言。
正常代词、固定称谓、专名和共同事实允许重复。不同条目的必要摘要允许重叠。

### 5. 不确定性与范围

约数、区间、传闻、推测、未完成事件保留原文精度，不收紧也不放宽。
“原文未交代”须检查已读范围后才写，不能以一个证据包没命中当成全文没写。
单纯缺材料可以省略字段或标 stub，不每节反复补“未写明”来凑篇幅。
所有“此后”“始终”“从未”都受已读范围限制。

### 6. 引文与考据

转述用自己的句法，直接引用使用引号并挂对应来源。
专名、官职和正常事实短语与原文重合是允许的；**连续六字重合不是事实或文风错误的充分条件**。
original_overlap_check 只用于找疑似整段照搬，不以零命中作为验收门槛，不要求为了避阈值换专名或删虚字。

sources 每条用 chapter、cite、quote 定位原文；一条引文不能跨来源段落拼接。
省略用“……”标示，保留语义与不确定性。quote 必须出现在所标章，不把转述放进引文。
lead_refs 和 sections[].refs 是从 1 起的 source 编号，每节引文只能在该节引用的 sources 中核对；
作品内评价可用 reception_refs.in_work 指向来源。旧示例的评价引文仍按条目内独立来源核验；
无正文编号的来源可作为补充材料，不为挂满每条来源而反复派模型。出处校验能验证字面与编号，
不能证明转述的含义完全正确。

### 7. 条目分工

事件页详述经过；人物页写生平要点与相关事件链接；地点、物品页写自身位置、特征与变化。
不同页可以各写足够让本页独立可读的摘要，不为跨条目零重复删掉必要事实。
评价按作品内、用户提供、外部资料区分；没有材料就不设评价节。
材料少时标 stub，不派额外模型仅为扩写或凑长度。

## 二、Vector 2022 风格站点

布局参照 [MediaWiki Vector 2022](https://www.mediawiki.org/wiki/Skin:Vector/2022)，
使用项目自己的站点名，不冒充维基百科。固定模板由脚本生成，不逐页让 AI 手写。

- 顶栏：主菜单、简洁站点标识与作品名、通往本地分类索引的入口。
- 桌面：左侧轻量目录，中间文章，右侧工具与外观。主体阅读宽度优先，边栏不做厚边框卡片。
- 标题与标签位于文章区上方；标题下细分隔线，阅读标签高亮，未提供的讨论、编辑、历史明确不可用。
- 信息框在正文内靠右浮动，不占右工具栏。相关条目放正文末尾。
- 目录每项链接到真实标题锚点，参考资料编号可跳转并展开引用区。
- 外观选项确实改变字号和正文宽度；没有实现的按钮不伪装可点击。
- 白底、细灰线、蓝色链接，标题以衬线字体为主，正文采用可用的本机中文字体。
- 首页先说明作品与覆盖范围，再按实体类型给出索引。
- 窄屏隐藏桌面侧栏，目录可折叠；信息框不挤窄正文，不产生横向滚动。
- 零外部资源请求，脚本可为零；外部参考资料链接是用户主动打开的链接，不算资源加载。
- 无条目生成时间，不把审查次数、模型调用、schema 等实现细节塞进页面。

## 验收

脚本检查来源、编号、文件与锚点；浏览器抽查一张有长文和信息框的桌面页、一张窄屏页。
内容自查先看归属、人称和歧义，再看行文。不以主语重复次数、字面重合次数作统一否决。
AI 抽样只按作品级参数执行，发现问题仅修相关材料，不循环全库改写。
