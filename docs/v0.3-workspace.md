# v0.3 工作区使用

先安装 `python -m pip install -r requirements-lock.txt`。从 skill 根目录运行下列命令。
本版是内核与 CLI，不含客户端上传按钮，不改变条目生成策略。

## 状态与兼容

SQLite 是正式状态来源，JSON 文件用于模型交换、旧检查器和导出。模型生成结果先落盘，再提交。
一批数据与任务完成状态同事务提交；输入变化、同 ID 不同内容、过期领取和旧稿覆盖会拒绝。
JSON 导出是可重建的副本，多文件导出中断后重跑 export 即可，不重新调用模型。
不要同时对同一个目录运行多个 export；子代理用 --no-export 先提交，主流程统一导出。

```powershell
# 清洗、保存输入原件和正文版本
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 ingest 输入.txt --author 作者
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 export out --kind chapters

# 旧项目仅首次迁移
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 import data

# 同一版本的独立追加批次
python scripts/merge_append.py work/append-001.json --base-dir data --prefix 书 --batch-id append-001 --no-export
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 export data

# 显示状态，不显示正文
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 status
```

workspace put 是明确替换单个文档的管理接口，用于人工确认的修订；并行模型任务应使用 task submit。
现有 convert、merge_entries、quote_source_check 等脚本仍可读取 JSON。
原稿在 sources/ 按内容 hash 保存，正文版本在数据库保存；规则和依赖版本变化会使 ingest 缓存失效。
尚未替换 MOBI、PDF、Calibre 后端，尚未实现 OCR。

## 任务

manifest 结构见 schema/子代理协议.md。输入必须冻结；路径/hash/range 均验证，任务输入默认最多 12000 字符。
任务 ID 在同一数据库内全局唯一。draft 的 expected_entries_hash 从 status 中读取；初稿为 null。

```powershell
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 task cache work/task.json
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 task prepare work/task.json
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 task claim draft-001
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 slice work/task.json --out work/input-small.txt
# 写作方按当前规范读取小片段，完整 JSON 写到 manifest.output
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 task submit draft-001 --token 领取返回的token
```

claim 返回的是执行 token，不是 API 密钥。租约内不能重复领取，过期后重领，旧 token 失效。
extract 合并新增记录；同身份不同内容会拒绝，需要明确修订。draft 替换全稿并检查引用和人称。
缓存命中返回原结果位置；改变输入、规则或配置会失效，结果文件被改动也不能命中。
review 任务存储执行状态，独立审查次数使用 review_plan 的作品级 SQLite 台账；JSON state 只是导出，丢失也不能重置额度。
task claim 不代替审查额度领取。review_plan 保留原审查策略和命令参数，新增可选 --db。

## 图片与书评

```powershell
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 target-id entries e-0001
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 upload image 图片.png --target-id 返回的稳定ID --metadata 图片说明.json --id image-001
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 upload review 书评.txt --target-id 返回的稳定ID --metadata 书评信息.json --id review-001
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 update-upload review-001 修订信息.json
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 delete-upload review-001
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 render 书_wiki --unit 章
```

图片说明可含 caption、source、order、cover；书评信息可含 title、author、source、date。
不传 target-id 则关联作品首页。图片支持 PNG/JPEG/GIF/WebP，导入时复制到 uploads/，原文件移动不影响显示。
删除上传记录不立即删除共享图片文件；重新渲染后不再显示。没有匹配到当前条目的上传会保留并报告。
书评是用户评价，不进入小说事实和引用来源；HTML 字符转义，仅提供用户声明的来源链接，不自动抓取网页。

## DSH 与缓存

专用 headless profile 应按顺序加载模型配置、config/dsh-core.patch.yml；不修改或卸载全局插件。
默认不加载其他 skill；当前项目规范按需 read。需要子代理时再加载 dsh-subagent.patch.yml，只允许 spawn。
可用 run_dsh.py 统一启动，指定已安装的 Node、DSH CLI 和模型配置；任务文件只写短指令及 manifest 位置。

```powershell
python scripts/run_dsh.py --node Node绝对路径 --cli DSH的desktop-cli.js绝对路径 --model-patch 模型配置.yml --credentials-file 现有凭据文件绝对路径 --task-file work/task-instructions.txt
```

启动器把 profile/session 放在当前项目的 .novel2wiki/dsh；凭据只引用原文件，不复制密钥、不修改全局 profile。
仅必要独立任务才加 --allow-subagent，保持整个运行的工具清单稳定，不在批次间随意切换。
固定角色指令参考 config/fixed-context.md；任务信息置后，不反复复制正文和工具结果。
本版不替用户保存 API 密钥。运行环境可使用其已有凭据配置，凭据文件不进入分发包。

audit_dsh.py 可以实际启动并在请求到达模型前拦截，检查工具和插件配置、重复上下文，模型调用次数为零。
usage / usage-summary 接口保存标准化真实用量事件，以请求 ID 去重；输入缺失不会被算作零成本。
缓存改善需同时观察未缓存输入、缓存读取、输出和总量，不能只报告命中率。

## 检查与备份

```powershell
python -m unittest discover -s tests -v
python scripts/convert.py --selftest
python scripts/build_distribution.py
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 backup backup/novel2wiki.sqlite
```

backup 使用 SQLite 备份 API，包含 WAL 已提交数据。它只备份数据库；完整项目备份还须保留 uploads/、sources/。
当前数据库 schema 为 1；未来未知版本会拒绝打开，防止用旧程序误写。
