# v0.3 工作区使用

先安装 `python -m pip install -r requirements-lock.txt`。从 skill 根目录运行下列命令。
本版是内核与 CLI，不含客户端上传按钮，不改变条目生成策略。

## 状态与兼容

SQLite 是正式状态来源，JSON 文件用于模型交换、旧检查器和导出。模型生成结果先落盘，再提交。
一批数据与任务完成状态同事务提交；输入变化、同 ID 不同内容、过期领取和旧稿覆盖会拒绝。
JSON 导出是可重建的副本，多文件导出中断后重跑 export 即可，不重新调用模型。
不要同时对同一个目录运行多个 export；子代理用 --no-export 先提交，主流程统一导出。

```powershell
# 清洗、保存输入原件和正文版本
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 ingest 输入.txt --author 作者
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 export out --kind chapters

# 旧项目仅首次迁移
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 import data

# 同一版本的独立追加批次
python scripts/merge_append.py work/append-001.json --base-dir data --prefix 书 --batch-id append-001 --no-export
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 export data

# 显示状态，不显示正文
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 status
```

workspace put 是明确替换单个文档的管理接口，用于人工确认的修订；并行模型任务应使用 task submit。
现有 convert、merge_entries、quote_source_check 等脚本仍可读取 JSON。
原稿在 sources/ 按内容 hash 保存，正文版本在数据库保存；规则和依赖版本变化会使 ingest 缓存失效。
尚未替换 MOBI、PDF、Calibre 后端，尚未实现 OCR。

## 任务

manifest 结构见 schema/子代理协议.md。输入必须冻结；路径/hash/range 均验证，任务输入默认最多 12000 字符。
任务 ID 在同一数据库内全局唯一。draft 的 expected_entries_hash 从 status 中读取；初稿为 null。

```powershell
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 task cache work/task.json
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 task prepare work/task.json
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 task claim draft-001
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 slice work/task.json --out work/input-small.txt
# 写作方按当前规范读取小片段，完整 JSON 写到 manifest.output
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 task submit draft-001 --token 领取返回的token
```

claim 返回的是执行 token，不是 API 密钥。租约内不能重复领取，过期后重领，旧 token 失效。
extract 合并新增记录；同身份不同内容会拒绝，需要明确修订。draft 替换全稿并检查引用和人称。
缓存命中返回原结果位置；改变输入、规则或配置会失效，结果文件被改动也不能命中。
review 任务存储执行状态，独立审查次数使用 review_plan 的作品级 SQLite 台账；JSON state 只是导出，丢失也不能重置额度。
task claim 不代替审查额度领取。review_plan 保留原审查策略和命令参数，新增可选 --db。

## 图片与书评

```powershell
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 target-id entries e-0001
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 upload image 图片.png --target-id 返回的稳定ID --metadata 图片说明.json --id image-001
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 upload review 书评.txt --target-id 返回的稳定ID --metadata 书评信息.json --id review-001
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 update-upload review-001 修订信息.json
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 delete-upload review-001
python scripts/workspace.py --db data/novel2wiki.sqlite --work 书 render 书_wiki --unit 章
```

图片说明可含 caption、source、order、cover；书评信息可含 title、author、source、date。
不传 target-id 则关联作品首页。图片支持 PNG/JPEG/GIF/WebP，导入时复制到 uploads/，原文件移动不影响显示。
删除上传记录不立即删除共享图片文件；重新渲染后不再显示。没有匹配到当前条目的上传会保留并报告。
书评是用户评价，不进入小说事实和引用来源；HTML 字符转义，仅提供用户声明的来源链接，不自动抓取网页。

## DSH 与缓存

专用 headless profile 应按顺序加载模型配置、config/dsh-core.patch.yml；不修改或卸载全局插件。
默认不加载其他 skill；当前项目规范按需 read。需要子代理时再加载 dsh-subagent.patch.yml，只允许 spawn。
可用 run_dsh.py 统一启动，指定已安装的 Node、DSH CLI 和模型配置；任务文件只写短指令及 manifest 位置。

```powershell
python scripts/run_dsh.py --node Node绝对路径 --cli DSH的desktop-cli.js绝对路径 --model-patch 模型配置.yml --credentials-file 现有凭据文件绝对路径 --task-file work/task-instructions.txt
```

启动器把 profile/session 放在当前项目的 .novel2wiki/dsh；凭据只引用原文件，不复制密钥、不修改全局 profile。
仅必要独立任务才加 --allow-subagent，保持整个运行的工具清单稳定，不在批次间随意切换。
固定角色指令参考 config/fixed-context.md；任务信息置后，不反复复制正文和工具结果。
本版不替用户保存 API 密钥。运行环境可使用其已有凭据配置，凭据文件不进入分发包。

audit_dsh.py 可以实际启动并在请求到达模型前拦截，检查工具和插件配置、重复上下文，模型调用次数为零。
usage / usage-summary 接口保存标准化真实用量事件，以请求 ID 去重；输入缺失不会被算作零成本。
缓存改善需同时观察未缓存输入、缓存读取、输出和总量，不能只报告命中率。

## 降低模型调度次数的批次收尾入口

```powershell
python scripts/workspace.py --db data/novel2wiki.sqlite --work 药 import data
python scripts/workspace.py --db data/novel2wiki.sqlite --work 药 finalize work/entries-b01.json work/entries-b02.json --directory . --report work/finalize-report.json
```

用此入口串行执行批次合并、八表/引文/人称/条目结构与链接校验、SQLite 提交、JSON 导出、固定模板渲染和站点检查。
程序不重写事实和引文，不自动纠错，不创建模型调用，也不领取审查次数。失败只回短摘要与报告路径；原正式正文和站点保持不变（渲染阶段发生故障时，已提交稿件可重跑恢复渲染）。
修改已有稿件需传 `--expected-hash <workspace status 的 entries hash>`，防止旧批次覆盖新稿；相同内容允许直接恢复中断的导出/渲染。
模型只读取当前步骤规范；正常运行不需要读取 Python 实现。不再逐项把这些确定性动作交给模型调度。

## v0.3 流程修补：证据包、局部修复与恢复

八表就绪后，先由程序准备写作输入：

```powershell
python scripts/workspace.py --db data/novel2wiki.sqlite --work 药 prepare-draft work/draft-context --chapter 2
```

返回 context（draft-context.json）、独立兼容文件的路径、context_chars、evidence_hash 和当前 expected_entries_hash，stdout 不带原文。
写作优先只读context一个文件，其中含guide、evidence与可选draft_template，不再读重复的独立副本。context_chars按该文件的真实序列化字符数计算（含换行）。
默认预算12000字符，含规范、证据和可选模板；超预算会拒绝，必须选择更小的章节范围，不会截断后假装处理全文。
证据包不含百科语料。写作方只读这个包和规范，不需要逐个读取 Python 实现与所有历史规范。

每批 meta 带返回的 evidence_hash；来源可写 `{"evidence_id":"c1p3"}`。ID 的 c 序号按冻结正文中的章节顺序，实际 chapter 来自记录，不按通行章名猜编号。
程序精确复制这个段落的原文并补 chapter/quote/cite。可选 start/end 为 Python Unicode 字符范围，通常不使用；如果同时给出 quote/chapter，必须与证据完全一致。
旧 quote 结构继续支持。旧版本hash、未知ID、错章、越界或内容冲突会拒绝，不用相似句偷偷代替，不自动修复小说事实。

finalize 的报告按阶段记录 committed / exporting / rendering / completed；未完成时 status 为 running 或 retryable，不能凭“已入库”宣称站点完成。
校验错误标出 affected_entry_ids，生成最多6000字符的 repair_packet，只含受影响条目及有限错误。过大的条目会明确标为省略，不会把整库发回模型。
修复的是本批草稿；未提交的新稿不覆盖旧正式稿。hint_count 是线索，不是失败，不要求提示归零，也不在未指定字数时逐字计数。

完成后，程序用正文、八表、上传、规则与输出文件hash核对缓存。输入不变且所有生成文件完整时返回 reused；缺页、文件变动、规则或上传变化会重建。
不把“缓存命中”当作语义质量保证。涉及导出/渲染中断，从报告中的 entries_hash 恢复：

```powershell
python scripts/workspace.py --db data/novel2wiki.sqlite --work 药 resume --directory . --report work/finalize-report.json --expected-hash <已提交的entries_hash>
```

无需重写正文，也不需要原来的批次文件。若报告丢失，用 status 查数据库中的 entries hash。旧hash不能恢复覆盖新稿。
渲染期间若正式稿/章节/八表被另一进程改动，本次不能报告完成，须以当前版本重新恢复；不要并行操作同一个导出目录。


### 直接用证据 ID 引用正文

新稿推荐 `sources: []`，`lead_refs: ["c1p3"]`，`sections[].refs: ["c1p3","c1p5"]`。
程序按首次使用顺序创建本条 sources，并把这些字符串换成 `[1]`、`[1,2]` 等整数引用；渲染器及旧导出结构保持兼容。
不用把“原文第9段”手工换算为“本条第3个来源”。ID为不透明标识，以记录内chapter为准，不能从c前缀推测实际章号。
如果提供已有 sources，保留其顺序，新的证据 ID 追加；使用同一 ID 的多个切片时请用原有整数 refs，不能让程序猜要指哪个切片。
finalize 和 worker task submit 都支持这个输入形式。程序只建立编号和复制原文，不判断正文断言是否被证据真正支持。

## compact-v1模板与局部更新

compact-v1为实验选项，未通过整体省耗与语义验收；默认不传--entry，仍用原lead格式。单包读取和局部更新均可独立使用，不依赖该实验格式。

```powershell
python scripts/workspace.py --db data/novel2wiki.sqlite --work 药 prepare-draft work/draft-context --chapter 2 --entry character e-0001 华大妈
```

每次明确选择1–3个对象；多个对象重复--entry，参数依次为kind、id、name。模板保留meta；正文只需lead_facts、lead_refs、sections及需要的links。
lead_facts必须非空，只写有据事实，不重复作者/作品定位句；程序从冻结title/creator和明确选择的kind生成首句。无作者元数据时不猜作者。
aliases/sources/links省略默认空数组，reception默认三个空栏，stub默认false；材料少可明确设true。程序不生成关系、经历、动机或评价。
展开后保存为旧版lead/sources结构；resume和渲染不需要重新生成，旧稿无需转换。worker draft提交也支持compact-v1，其任务仍为完整稿替换。
已有编辑过的draft.json不会被再次prepare覆盖；上下文或范围不同需换目录。

```powershell
python scripts/workspace.py --db data/novel2wiki.sqlite --work 药 finalize work/edited-entry.json --update --expected-hash <当前entries_hash> --directory . --report work/finalize-report.json
```

--update对输入的完整条目按ID新增或更新，保留其余已提交条目；不是逐字段patch。必须提供当前hash；同ID改名或改kind会拒绝，跨条链接在合并后检查。
保留既有整稿scope/author，不允许局部稿悄悄改变阅读范围；原元数据缺失时允许补入。对完整合并结果仍做引用、人称、链接和站点检查。
不加--update时仍按完整稿件集合提交；如将移除既有ID，必须明确加--replace，且仍受版本hash检查。首次提交不需要这两个标志。
校验聚合多条结构错误和多个批次的引用错误；缺ID行用entry[n]定位，修复包含有限元数据及受影响条目，最多6000字符。
返回completed/reused后停止重复机械检查。机械通过仍不能保证改写含义正确；语义疑点只核对相应段落。
