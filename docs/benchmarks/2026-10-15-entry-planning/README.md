# v0.3 条目规划与公共设定页验证

已实现有据判断后的条目去向、主题边界、主次深度，以及种族/设定公共页和关系链接。没有预置属性名、品阶值、等级顺序或成员名单。程序通过不等于判断或转述语义正确；本轮真实模型质量与省耗仍未验收。

## 实现与机制验证

- 完整候选留文件，分包判断；unknown不当mention。种族候选也先判断，新增设定用通用concept。公共页可以概括整个体系，不自动为每个属性值造页。
- 每项保留独立、短页、并入、留表或待判断的去向；重要性看独立身份、关键作用与证据，频次只是定位线索。篇幅无最低字数，主题数只设上限。
- topics约束主题、标题与证据；拒绝空节、错主题、跨主题借引用、丢失并入主体或将其当alias。模型仍可能写出没有证据支持的概括，机械校验不能识别全部语义问题。
- 每条所属/层级/参与关系有独立证据，反向关系分别判断；新公共页发布后旧人物页自动显示链接，无需重写人物正文。默认重建保留旧关系，显式空列表才清空；过期关系来源要求复核。
- 上下文12000字符、清单摘要6000字符；写作只带本批证据。长章节可明确选段并报告部分范围。来源过期拒绝，resume保留计划覆盖状态，缺页/未决/未核验旧页与站点completed分别报告。
- 虚构“雾裔/弦序”端到端例生成4页；回枝/无环没有被自动拆页，石扣仍待判断，历史记录不被推成当前状态。该例不是《龙族》事实标准答案。

## 真实短文对照

重复使用《药》同一727字符节选，两个人物页；两轮各自冻结候选，是自适应调试，不合并为同版本统计重复。对照为b4262e0；两边同quality-v2写作规约、Flash/high、8192上限、11工具。规划组包含模型判断、决策文件、上下文准备、写作和返修，不能只计算最终写作费用。

第一轮规划组把短条压到只剩日常习惯，丢失出场问话、无人应答和泡茶；“包馒头”标题也容易错置主体。第二轮短条恢复了具体行动，但漏掉闻香；主条仍漏一处劝睡附带的疗效说法，标题“服药”将人物治病意图当成客观性质，并补足了凳子的安放者和让坐关系。对照稿也存在标题定性、动作细化与覆盖缺口。完整覆盖不等于事实零错误。

第二轮将新规划包改为分行JSON和规则数组，避免单行阅读工具省略长行。仍观察到多读规范、决策顶层擅加batch/scope被拒绝及多次自改。随后补了独立decision_template、顶层键提示和通用标题/导语分工指引；这些后续调整只做程序回归，未另跑第三轮模型，也不据此宣称费用或事实已改善。

## 交付边界与下一步

规划接口为显式--plan选项，旧无计划入口及默认legacy写作提示词保留。quality-v2仍是实验项。当前可验证的是去向保留、结构、来源绑定与页面关系；重要性判断、标题和正文语义仍需当前执行者核对，不声称“条目质量已解决”。

开发想法已记录：把决策与正文各自只写一次的受控执行入口、显式保留核心事实的分配记录、面向不同作品的小样本复测；不通过固定作品词表、自动等级排序或继续叠全库代理解决。小模型和百科语料继续暂缓。
