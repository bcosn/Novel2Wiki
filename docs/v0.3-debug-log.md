# v0.3 调试与打包日志

日期：2026-10-15（Asia/Shanghai）。起点：`8276a962814c7a41644975648e2d270d98ed2d1c`。

本轮只用少量虚构数据和现有程序回归，不新增真实小说模型调用，不使用维基语料。先复现，再修复、回归与打包；没有重跑上一轮生成费用对照，也不宣称质量或省耗已经改善。

## 已复现并修复

1. **当前章节包混入未来时间线**：原先只筛chapter/first_chapter，会把第11章状态放进第7章判断包。现在按人物/物品状态区间与所选章号的交集取数据，非连续章不填补中间空档；未来结束边界仅在包副本中隐藏，正式表保持原样。
2. **未发布公共页阻断计划重建**：人物页已有指向未发布concept的关系，但重建时不知道其身份。现在已验证的完整计划以`_entry_plan`元数据文档与正文同事务存入SQLite，重建恢复尚未发布的候选、主题与关系。仍是八张事实表，没有把小说正文复制进计划或消息。无效稿不推进已保存计划，旧来源不自动重新绑定。
3. **旧工作区恢复缺少入口**：此前仅保存外部计划的工作区，可用`plan-entries ... --base-plan 原计划.json`恢复；过期原计划明确拒绝，要求按新来源重新判断。
4. **特殊标题链接断裂且漏检**：标题含`#`、字面`%20`或空格时，原href可能被浏览器当作片段或解码后的另一文件。多页链接和单页片段现在对原始值统一编码；磁盘名不改，中文仍可读。站点检查验证实际本地目标及锚点，不再按后缀跳过问题链接。
5. **单页引用锚点撞上条目ID**：`e-person`的来源锚点可能和条目`e-person-ref1`同名。现在为程序来源锚点避让实际ID，避免引用跳错。
6. **同名冲突发现太晚**：种族与设定同名曾在正文写完后才报错。现在准备写作前就检查所有已批准独立标题，以及将保留的已发布标题，要求先消歧。
7. **空章节选择扩大为整书**：底层catalog把空列表当作未指定范围。现在显式空范围、布尔章号、非正整数及错误类型直接拒绝，准备失败不写输出。
8. **已删除关系从旧计划复活**：恢复元数据时，“从未发布”与“发布后删除”必须区分。现用SQLite记录历史识别两者，显式删除过的页及其旧来源关系不再自动恢复；基础表中仍存在的对象保留review，需重新判断才建页。
9. **解压后的旧回归缺少目录初始化**：首次解压复验中，33项flow测试因`.validation`目录不存在而无法启动；源码目录已有该目录所以没有暴露。现在测试自行创建它，干净解压可直接执行。首次失败日志保留，不混入通过记录。

## 验证

- 全量：`python -m unittest discover -s tests`，180项通过。
- 本轮新增21项：时间线范围5项、链接/锚点5项、持久化恢复与边界11项。
- 小型端到端：先发布人物/种族，再恢复未发布设定页；旧人物正文不重写、关系保留、已删除关系不复活、无效稿不改正式计划/正文/站点、旧工作区恢复保持只读。
- 故障注入：计划写入后模拟正文保存失败，计划与正文全部回滚，不留下半提交。
- 分发：ZIP按公开文件清单重建；归档CRC与源码对应由程序检查，不含SQLite、凭据、用户小说、运行会话或临时工作目录。另从分发包解压运行回归，确认不是只在开发目录可用。
- 质量边界：这些回归验证数据、范围、链接与恢复机制，不能证明模型的分类、标题或正文语义正确。上一轮两次真实对照增费37.29%/53.61%的结论保留。
